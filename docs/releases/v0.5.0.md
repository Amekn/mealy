## What changed

- A threshold-signed skill and extension registry format binds out-of-band trust roots, monotonic
  snapshots, publisher identities, immutable release/package descriptors, compatibility and
  dependency locks, withdrawals, and exact permission diffs. Fetch and staging are inert;
  installation is disabled by default and never grants runtime authority.
- Registry-backed skills and extensions support review-digest-fenced install, update, rollback,
  and provenance adoption. The daemon rechecks current signed policy before activation and every
  extension invocation, while retaining immutable bytes and audit history after withdrawal.
- Optional semantic memory adds explicitly configured local or remote embeddings as a rebuildable
  derived index. Canonical scope and sensitivity filters run before deterministic lexical/vector
  fusion; correction, deletion, policy drift, or incomplete rebuild makes the index stale and
  automatically falls back to literal retrieval.
- Revisioned one-shot and future-event automations add prompt or static-notification actions,
  exclusive no-replay cursors, leased crash recovery, durable deduplication, lifecycle controls,
  and run history. Event notifications never copy the triggering private payload.
- A local owner can pin one previously admitted Slack thread for proactive automation
  notifications. The route is UUIDv7-keyed, expiring, single-owner, revision-revocable, and
  revalidated at definition, outbox publication, and delivery claim without latest-thread or local
  fallback. Proactive Slack prompts remain prohibited.
- The stable blocking Rust SDK covers health, providers, session workbench, text/image admission,
  task control and replay, approvals, automations, extensions, and channel administration through
  the versioned authenticated API with HTTPS, redirect, proxy, credential, and response bounds.
- Opt-in OpenTelemetry exports content-free claimed-run traces and fixed-label outcome metrics with
  bounded batching and shutdown. Versioned evaluation suites execute fresh public-API sessions and
  emit digest-bound content-free reports for deterministic task, safety, replay, budget, latency,
  and cost assertions.
- State schema 30 adds reconstructible registry trust/package provenance, semantic-index state,
  revisioned automations, and exact-thread Slack continuation records.

## Upgrade considerations

- Linux remains the production contract: Ubuntu 24.04/26.04, Debian 13, and Fedora 44 on
  x86-64/ARM64, plus current Arch Linux on x86-64. Compatible derivatives remain expected rather
  than certified; macOS, Windows, musl-only, and non-FHS systems remain outside this release.
- Release qualification independently upgrades exact attested v0.4.0/schema-23 and
  v0.3.0/schema-18 installations to v0.5.0/schema 30 on every supported package-manager lane. Keep
  the generated pre-migration snapshot until v0.5 is accepted for the owner workload.
- Registry bootstrap requires an owner-selected mirror and out-of-band root review. Mealy does not
  ship a universal public registry, execute discovery metadata, or turn requested permissions into
  grants. Registry publication tooling remains outside this release.
- A semantic rebuild may send every in-scope active memory revision to the configured embedding
  endpoint. Use a local server when the content must not leave the host; remote use requires an
  explicit HTTPS endpoint, residency choice, and brokered credential.
- The SDK is blocking Rust only. The release includes reproducible publishable `mealy-domain`,
  `mealy-protocol`, and `mealy-client` crate archives, an exact consumer lock, checksums, and
  retained Sigstore provenance; qualification compiles a clean consumer from both built and public
  downloaded packages against frozen v0.2.1/v0.3/v0.4/v0.5 daemon fixtures. These assets are not
  a claim of crates.io publication. Async and non-Rust SDKs, authenticated OTLP collectors, broader
  attempt/effect/scheduler instruments, signed evaluation-report publication, and model-judge
  plugins remain later ecosystem work.
- Remote continuation is outbound notification-only and bound to an exact previously admitted
  Slack thread. General remote interactive prompts, inbound public listeners, additional
  continuation transports, and multi-user hosting remain outside v0.5.
