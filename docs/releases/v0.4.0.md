## What changed

- Durable delegation now supports bounded parallel child groups with explicit depth, fan-out,
  token, tool, time, cost, and resource ceilings. Child contexts and authority remain isolated;
  cancellation, owner steering, handoffs, and deterministic aggregation are canonical durable
  state rather than prompt-only coordination. The terminal workbench shows recent child
  state/lineage cards, while the temporary dashboard offers bounded read-only inspection of exact
  child authority, budget, state, and structured result.
- Remote Streamable HTTP MCP support adds separately governed tools, exact resources, prompts,
  protected-resource discovery, OAuth/OIDC metadata inspection, and public-client
  authorization-code login with PKCE S256. Read-only, idempotent, and non-idempotent tools use
  distinct approval, retry, reconciliation, and recorded-replay rules.
- Bounded PNG, JPEG, and WebP input is available through the authenticated API and scriptable CLI.
  Images are normalized in isolation, stripped of metadata, stored as content-addressed private
  artifacts, and rejected before provider dispatch when a route cannot accept them.
- Separately configured image generation is a high-risk non-idempotent effect with exact owner
  approval, provider/model/cost/output ceilings, isolated output normalization, durable settlement,
  and no automatic retry after ambiguous dispatch.
- A reusable channel boundary now includes a production Slack Socket Mode adapter. It binds one
  verified workspace, app, bot, owner, and conversation; persists every admit/ignore decision
  before acknowledgement; recovers acknowledged work after restart; and returns bounded output to
  the exact originating thread. Slack messages cannot approve effects.
- The optional one-shot transactional browser effect can submit one revalidated same-origin POST
  form with exact approved fields and digest-bound uploads, then capture at most one bounded
  response download. It uses a fresh isolated target, never retries ambiguous submission, and is
  separate from the safer read-only browser.
- State schema 23 adds reconstructible delegation groups, remote MCP/OAuth state, media linkage and
  generation evidence, Slack delivery state, effect-budget reservations, and browser transaction
  provenance.

## Upgrade considerations

- Linux remains the production contract: Ubuntu 24.04/26.04, Debian 13, and Fedora 44 on
  x86-64/ARM64, plus current Arch Linux on x86-64. Compatible derivatives remain expected rather
  than certified; macOS, Windows, musl-only, and non-FHS systems remain outside this release.
- The first v0.4 start migrates durable state from schema 18 to schema 23. Keep the generated
  pre-migration snapshot until v0.4 is accepted for the owner workload. Do not start a v0.3 binary
  directly against a schema-23 home; use the approved migration-snapshot rollback workflow.
- Release qualification upgrades the exact attested v0.3.0 installation to v0.4.0 on every
  supported package-manager lane and verifies existing sessions, replay, owner identity, package
  removal, backup/restore, and the schema-18-to-23 rollback boundary.
- Image input is available through the authenticated API, scriptable CLI, full-screen TUI, and
  temporary owner-local dashboard. TUI attachments use the same no-follow path boundary and render
  path-free evidence; dashboard uploads are browser-selected and its PNG/JPEG preview rechecks
  immutable size/media/digest evidence. Line-chat/channel image UX, terminal pixel protocols,
  reference/edit workflows, audio, and video remain outside v0.4.
- MCP dynamic client registration, resource-template expansion and subscriptions, resumable
  streams, persistent browser profiles, ambient login, payments, cross-origin transactions, and
  unattended browser batches remain outside this release.
- Signed registry distribution, semantic retrieval, event automation, stable SDK/telemetry/eval
  packages, and remote continuation are v0.5 capabilities rather than being implied by v0.4.
