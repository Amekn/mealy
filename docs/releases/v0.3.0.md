## What changed

- A canonical session workbench now provides safe derived and owner-edited titles, bounded search,
  checkpoints, fresh-lineage forks, and digest-verified JSON or inert self-contained HTML transcript
  exports. These features share daemon-owned state across the scriptable CLI, full-screen terminal
  client, and loopback dashboard.
- `mealyctl tui` adds a full-screen terminal workspace with a session/search rail, verified
  conversation timeline, bounded composer, active/queued work, provider/context/cost status,
  structured recent activity, exact approval review, and checkpoint/fork/export controls. It
  restores terminal state after normal exit, cancellation, panic, resize, or daemon loss.
- The authenticated provider catalog reports the exact configured route chain, capabilities,
  locality, declared limits/prices, health, and pressure. Owners can select one compatible route
  for a new conversation or next turn without changing already-admitted work.
- `mealyctl provider switch` adds a review-first, restartable promotion of an already-configured
  compatible fallback. Approved switches probe the target, drain, atomically reorder the complete
  chain, restart and qualify the exact installed service, and automatically restore the prior
  configuration if activation cannot be qualified.
- Provider-switch and program-update helpers share one service-mutation lock, retain private
  digest-bound recovery evidence, and work across supported systemd-user implementations without
  weakening trusted `systemctl` identity checks.
- Timeline pages and latest-cursor reads now walk the cursor index first and perform bounded
  primary-key lineage checks. This prevents concurrent workbench, terminal, and dashboard refreshes
  from rebuilding a long-lived session's complete aggregate history.
- State schema 18 adds reconstructible session metadata/search, checkpoint/fork lineage, transcript
  export evidence, provider catalog selection, and associated context-rotation records. A verified
  v0.2.1 home is migrated through the existing pre-migration snapshot boundary; package rollback
  across the schema change requires the documented approved migration-snapshot activation.

## Upgrade considerations

- Linux remains the production contract: Ubuntu 24.04/26.04, Debian 13, and Fedora 44 on
  x86-64/ARM64, plus Arch Linux on x86-64. Compatible derivatives remain expected rather than
  certified; macOS, Windows, musl-only, and non-FHS systems remain outside this release.
- Provider switching only reorders routes that already exist and remain valid as a complete trust
  chain. Adding or removing routes, changing endpoint/model/credential/price/locality/residency,
  and environment-only credential activation remain explicit stopped-daemon operations.
- The first v0.3 start migrates durable state from schema 16 to schema 18. Keep the generated
  pre-migration snapshot until the v0.3 release is accepted for the owner workload. Do not start a
  v0.2.1 binary directly against a schema-18 home.
- Release qualification downloads the attested public v0.2.1 native package and upgrades that
  exact installation to v0.3.0 on every supported package-manager lane. It requires the existing
  session, task, recorded-only replay, and owner identity to survive; verifies exactly one
  schema-16-to-18 rollback snapshot; creates new title/checkpoint state; and proves package removal
  leaves the migrated owner home intact.
- Rich media viewers, parallel subagent cards, Streamable HTTP MCP, Slack, transactional browser
  writes, registry distribution, semantic memory, event automation, SDK/telemetry/evaluation
  packages, and remote continuation remain planned for v0.4 or v0.5 rather than being implied by
  this release.
